# Phase 208 — SENSEX Expiry-Squeeze Observation Journal

## Scope and status

This phase adds a provider-neutral, research-only append-only journal for
SENSEX option and index observations. It is an ingestion/storage foundation,
not a complete market-data connector or an executable strategy. No exchange
credentials, network requests, order APIs, backtests, or ML training are added.

## Event contract

The schema is quantengine.expiry_squeeze.event.v1 and stores:

- session ID and monotonically increasing arrival sequence;
- event type (option-chain snapshot, option quote/trade/book, 1-minute option
  and index candles, 5-minute index candles, candidate/rejection/outcome
  labels, and session markers);
- exchange timestamp and local receipt timestamp, both normalized to UTC;
- normalized instrument identity (exchange, underlying, expiry, strike, CE/PE,
  provider symbol where applicable);
- provider-normalized payload, previous-event hash, and event hash.

The journal is JSONL, strict-JSON (NaN/Infinity rejected), append-only through
the recorder API, and fsynced after each event. Its SHA-256 chain is verified
on every restart. A truncated, malformed, out-of-order, cross-session, or
modified-without-rehash journal is rejected; it is never silently repaired.
This hash chain detects accidental changes and edits that do not recompute the
chain. It is NOT a digital signature or an adversarial tamper-proof anchor: an
actor able to rewrite the entire file can recompute the chain. A future
certification step must externally sign or anchor the final session digest.
One writer owns each session file. Hard event and byte budgets stop capture
without deleting earlier evidence.

## Candidate handling

Candidate observations are data records, not orders. OBSERVED, ELIGIBLE,
and REJECTED are preserved with the decision timestamp, premium, feature
snapshot, and rejection reasons. Rejected candidates are first-class evidence.
Every candidate event explicitly records action_authorized=false.
Candidate IDs are deterministic over session, instrument, and decision time.

## Explicit non-goals / unresolved integration

1. No provider has been selected. A BSE/NSE-capable market-data provider must
   supply option-chain, quote/trade/book, and underlying-index feeds.
2. No assumption is made that the current Delta perpetual-futures adapter can
   provide SENSEX options; it is deliberately not reused for this market.
3. No premium, strike-distance, compression, volume, spread, IV, OI, or index
   confirmation threshold is promoted to a trading rule by this phase.
4. No 4-minute bars are synthesized here. The eventual adapter/feature layer
   must document timezone, session boundaries, candle-close semantics, and
   whether a 4-minute bar is aligned to 09:15 or another explicitly declared
   anchor.
5. The 101-bar / 6h44m volume-history requirement from the prior research
   specification remains an explicit warm-up/data-availability constraint.
6. Future-path labels (1/3/5/10/15/30 minutes, MAE/MFE, multiples/R) must be
   generated only after the horizon has elapsed and must retain the exact
   decision-time snapshot. No label is generated by this recorder.

## Safety boundary

The package imports no execution, broker, risk, or live-order modules. It
cannot place/cancel orders. The wider QuantEngine release posture remains
HOLD / NOT_PRODUCTION_READY and strategy edge remains NOT_ESTABLISHED.
